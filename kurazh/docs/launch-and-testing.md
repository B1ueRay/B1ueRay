# Kurazh: запуск и проверка на iPhone

*Call it or do it.* Пошаговая инструкция для владельца продукта. Программировать не нужно, нужны доступ к репозиторию `B1ueRay/B1ueRay` на GitHub, Google-аккаунт и два устройства (iPhone 15 Pro Max и второй телефон или компьютер).

Роли в приложении:

- **Caller** пишет задания (dares), ставит на них деньги и голосует, засчитать ли задание;
- **Taker** выходит в эфир и выполняет задания или отказывается от них по своим правилам.

> Эта сборка тестовая. Названия кнопок в разделе 3 даны по плану разработки: если в приложении надпись немного отличается, ориентируйтесь по смыслу. Если экрана нет совсем, запишите это как баг по шаблону из раздела 3.9.

## 1. Публикация

### 1.1. GitHub Pages (основной способ)

Сайт собирается автоматически: workflow `.github/workflows/kurazh-pages.yml` берёт папку `kurazh/` и публикует её. Сборка не нужна, приложение состоит из статических файлов.

1. **Слейте PR #3.** Откройте `https://github.com/B1ueRay/B1ueRay/pull/3`. Внизу нажмите **Merge pull request**, затем **Confirm merge**. Если кнопка серая, сначала нажмите **Ready for review** (если PR в черновике) и дождитесь зелёных проверок.
2. **Включите Pages из Actions.** В репозитории откройте **Settings → Pages**. В блоке **Build and deployment** в поле **Source** выберите **GitHub Actions**. Ничего больше на этой странице выбирать не нужно, кнопки Save здесь нет.
3. **Запустите workflow.** Обычно он запускается сам после слияния PR. Если на вкладке **Actions** нет нового запуска: **Actions → Kurazh · GitHub Pages → Run workflow →** ветка `main` **→ Run workflow**.
4. **Дождитесь зелёной галочки** (1–3 минуты). Если запуск красный, откройте его, нажмите на красный шаг и скопируйте текст ошибки в баг-репорт. Жёлтые предупреждения (`warning`) про отсутствующие `legal/privacy.html`, `support.html` и т. п. не мешают публикации: эти страницы готовят другие команды.
5. **Откройте сайт:** **https://b1ueray.github.io/B1ueRay/**. Эта же ссылка есть в запуске workflow (шаг **Deploy**) и в **Settings → Pages** («Your site is live at …»).

Как обновлять: каждое изменение в папке `kurazh/` в ветке `main` публикуется заново автоматически. Чтобы просто перевыложить сайт, повторите шаг 3.

> **Почему после обновления видна старая версия.** Приложение работает офлайн и кэширует файлы на телефоне. Новая версия подтягивается в фоне. Откройте приложение, подождите 5–10 секунд, полностью закройте его (смахните вверх) и откройте снова. Если не помогло: Safari → **aA** в адресной строке → **Website Settings**… или Настройки iPhone → **Apps → Safari → Advanced → Website Data** → найдите `b1ueray.github.io` → смахните влево → **Delete**. Внимание: это стирает и все тестовые данные приложения на этом устройстве.

### 1.2. Запасной вариант за 2 минуты: Netlify Drop

Подходит, если GitHub Pages ещё не настроен или сломан.

1. Скачайте папку `kurazh` на компьютер: на странице репозитория **Code → Download ZIP**, распакуйте архив. Нужна папка `kurazh` целиком (внутри должен лежать `index.html`).
2. Откройте **https://app.netlify.com/drop** и перетащите папку `kurazh` в окно браузера.
3. Через несколько секунд Netlify покажет адрес вида **`https://<случайное-имя>.netlify.app/`**. Используйте **именно его** (корень сайта, без `/B1ueRay/` в конце).
4. Без входа в аккаунт Netlify сайт временный и через какое-то время удаляется. Чтобы сохранить его, войдите в Netlify (можно через GitHub) и нажмите **Claim / Save site**. Имя сайта можно сменить в **Site configuration → Change site name**, тогда адрес станет, например, `https://kurazh-test.netlify.app/`.
5. Для входа через Google добавьте этот адрес в Google Cloud как отдельный источник (раздел 2.2, шаг 4).
6. Workflow на Netlify не работает, поэтому Client ID туда сам не попадёт: вставьте его в приложении в **Developer settings** (раздел 2.3, способ Б).

Netlify подходит для одного-двух дней тестов. Основной адрес для тестов и для Google: `https://b1ueray.github.io/B1ueRay/`.

## 2. Вход через Google

Приложение использует Google Identity Services: окно входа Google открывается поверх приложения (popup). Для этого нужен **Client ID**, публичный идентификатор вида `123456789012-abc...xyz.apps.googleusercontent.com`. Он не секретный, его можно хранить в настройках репозитория.

> **Никогда не вставляйте Client secret** (строка, которая начинается с `GOCSPX-`) ни в репозиторий, ни в приложение, ни в чат. Приложению он не нужен. Workflow откажется публиковать сайт, если найдёт такую строку в папке `kurazh/`. Если секрет утёк, удалите его в Google Cloud (**Clients → ваш клиент → Client secrets → Delete**) и создайте новый.

### 2.1. Экран согласия (OAuth consent screen)

1. Откройте **https://console.cloud.google.com/** и войдите своим Google-аккаунтом.
2. Вверху слева нажмите на выбор проекта → **New project**. Название: `Kurazh`. Нажмите **Create** и выберите этот проект.
3. Меню ☰ → **APIs & Services → OAuth consent screen**. В новом интерфейсе Google этот раздел называется **Google Auth Platform**, внутри вкладки **Branding**, **Audience**, **Clients**, **Data Access**. Если видите кнопку **Get started**, нажмите её.
4. Заполните:

   | Поле | Значение |
   | --- | --- |
   | App name | `Kurazh` |
   | User support email | ваш Gmail |
   | Audience / User type | **External** |
   | Developer contact email | ваш Gmail |
   | Authorized domains (вкладка **Branding**) | `github.io` (если используете Netlify, добавьте ещё `netlify.app`) |
   | Application home page | `https://b1ueray.github.io/B1ueRay/` |
   | Application privacy policy link | `https://b1ueray.github.io/B1ueRay/legal/privacy.html` |
   | Application terms of service link | `https://b1ueray.github.io/B1ueRay/legal/terms.html` |
   | Логотип | не загружайте: с логотипом приложение уйдёт на проверку Google |

   Ссылки на политику и условия должны открываться. Проверьте их в браузере после публикации. Если страница пока не готова (ошибка 404), сохраните экран всё равно и вернитесь позже: в режиме тестирования это не блокирует вход.
5. **Data Access / Scopes:** ничего не добавляйте. Приложению нужны только базовые `openid`, `email`, `profile`, они есть по умолчанию.
6. **Audience → Publishing status:** оставьте **Testing**. Не нажимайте **Publish app**: для теста это не нужно.
7. **Audience → Test users → Add users:** добавьте свой Gmail и Gmail второго тестировщика. В режиме Testing войти могут только эти адреса (до 100 человек).

### 2.2. Client ID

1. **APIs & Services → Credentials → Create credentials → OAuth client ID** (в новом интерфейсе **Google Auth Platform → Clients → Create client**).
2. **Application type:** **Web application**. **Name:** `Kurazh web`.
3. **Authorized JavaScript origins → Add URI:** `https://b1ueray.github.io`
   Только домен: без `/B1ueRay/`, без косой черты в конце, обязательно `https://`.
4. Если используете Netlify, добавьте второй источник: `https://<имя>.netlify.app`. Для проверки на компьютере можно добавить `http://localhost:8080` и `http://localhost`.
5. **Authorized redirect URIs:** оставьте пустым. Вход через всплывающее окно их не использует.
6. **Create.** Скопируйте **Client ID**. Client secret не копируйте и никому не отправляйте.
7. Изменения в Google вступают в силу от 5 минут до нескольких часов. Если сразу после создания вход не работает с ошибкой `origin_mismatch`, подождите 10–15 минут.

### 2.3. Как передать Client ID приложению

**Способ А (рекомендуется): переменная репозитория.**

1. GitHub → репозиторий → **Settings → Secrets and variables → Actions**.
2. Вкладка **Variables** (не Secrets) → **New repository variable**.
3. **Name:** `KURAZH_GOOGLE_CLIENT_ID`. **Value:** ваш Client ID. **Add variable**.
4. Перезапустите публикацию: **Actions → Kurazh · GitHub Pages → Run workflow → main**.
5. В итогах запуска появится строка «Google client ID injected: …». Workflow проверяет формат ID и не опубликует сайт, если в значении опечатка.
6. На iPhone закройте и снова откройте приложение (см. примечание о кэше в разделе 1.1), иначе телефон может показать старый `config.js`.

**Способ Б (быстро, только для одного устройства): Developer settings в приложении.**

1. Откройте приложение → **Profile → Developer settings** (если пункта нет в профиле, ищите его в **Settings** внизу профиля).
2. Вставьте Client ID в поле **Google Client ID** и сохраните.
3. ID сохраняется только на этом устройстве и в этом браузере. Установленное на экран «Домой» приложение на iPhone хранит данные отдельно от Safari, поэтому вставьте ID и там.

### 2.4. Частые ошибки

| Что видите | Причина | Что делать |
| --- | --- | --- |
| `Error 400: origin_mismatch` | Адрес сайта не добавлен в **Authorized JavaScript origins** или добавлен с путём или косой чертой | Добавьте ровно `https://b1ueray.github.io` (или ваш адрес Netlify), сохраните, подождите 10–15 минут |
| `Error 401: invalid_client` или «The OAuth client was not found» | Опечатка в Client ID или клиент удалён | Скопируйте ID заново из **Credentials**, обновите переменную или Developer settings |
| «Access blocked: Kurazh has not completed the Google verification process» (`403 access_denied`) | Ваш Gmail не добавлен в **Test users** | **Audience → Test users → Add users** |
| «Google hasn't verified this app» | Нормально для статуса Testing | Нажмите **Continue**. Для теста публиковать приложение и проходить проверку Google не нужно |
| Кнопка Google не появляется | Нет Client ID, нет интернета или блокировщик рекламы режет `accounts.google.com` | Проверьте раздел 2.3, отключите блокировщик контента для сайта (**aA → Turn off Content Blockers**) |
| Окно Google не открывается («popup blocked») | Safari блокирует всплывающие окна | Нажимайте кнопку Google пальцем ещё раз (окно открывается только по нажатию). Настройки → **Apps → Safari → Block Pop-ups**: выключите на время теста |
| Окно Google открылось, вход прошёл, а приложение «висит» | Особенность iOS: в приложении на экране «Домой» окно входа открывается в отдельном листе Safari и иногда не может вернуть результат | Сначала проверьте вход в обычном Safari. В установленном приложении закройте лист входа, нажмите кнопку ещё раз. Если повторяется, запишите баг: это известное ограничение iOS, его решает серверный вход (раздел 5) |
| После входа в Safari приложение на экране «Домой» снова просит войти | На iPhone у установленного веб-приложения своё хранилище, отдельное от Safari | Это ожидаемо: войдите ещё раз внутри установленного приложения |
| Подсказка One Tap («Continue as …») перестала появляться | Google временно скрывает её после нескольких закрытий | Используйте обычную кнопку **Sign in with Google**. Подсказка вернётся сама |
| Вход работает в Safari, но не в Chrome на iPhone | Chrome на iOS использует тот же движок, но свои настройки cookies | Проверяйте в Safari, Chrome на iOS — второй приоритет |

## 3. Сценарий проверки на iPhone 15 Pro Max

**Что понадобится:**

- **Устройство A:** iPhone 15 Pro Max, актуальная iOS, Safari. На нём вы **Taker**.
- **Устройство B:** второй телефон или компьютер с Chrome/Safari. На нём **Caller**. Для входа через Google на B нужен второй Gmail из списка Test users.
- Оба устройства в одной Wi-Fi-сети (см. раздел 4 про мобильный интернет).
- Заряд от 50%, звук включён, режим «Без звука» выключен (переключатель Action Button / боковой).

Отмечайте каждый шаг: ✅ совпало с ожиданием, ❌ не совпало (заполните баг-репорт), ⏭ пропущен (напишите почему).

### 3.1. Установка

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | На A откройте Safari, введите `https://b1ueray.github.io/B1ueRay/` | Тёмный экран Kurazh загружается за 3 секунды или быстрее на Wi-Fi. Нет белых полей, текст не уходит под «чёлку» (Dynamic Island) и под полоску «Домой» внизу |
| 2 | Нажмите **Поделиться** (квадрат со стрелкой) → **Add to Home Screen** (на новых iOS может быть в **⋯ More**). Убедитесь, что включено **Open as Web App**, нажмите **Add** | На экране «Домой» иконка Kurazh с правильной картинкой и подписью `Kurazh` |
| 3 | Откройте Kurazh с экрана «Домой» | Приложение открывается на весь экран, без адресной строки Safari. Строка состояния читается (часы и батарея видны) |
| 4 | Включите **Авиарежим**, закройте приложение и откройте снова | Приложение открывается из кэша (офлайн). Вход через Google и эфиры честно сообщают «нет сети», ничего не зависает. Выключите авиарежим |
| 5 | Поверните телефон горизонтально | Интерфейс остаётся вертикальным или аккуратно перестраивается, ничего не обрезано |

### 3.2. Вход через Google, профиль и возраст

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| 6 | Нажмите **Sign in with Google** | Открывается окно Google со списком аккаунтов |
| 7 | Выберите Gmail из Test users. Если Google пишет «hasn't verified this app», нажмите **Continue** | Окно закрывается, вы в приложении. Имя и фото взяты из Google |
| 8 | Откройте **Profile** | Видны имя, email, аватар и ник. Ник можно изменить. Ник с запрещённым словом (например, `vodka_king`) не сохраняется, приложение объясняет почему |
| 9 | На шаге проверки возраста укажите дату рождения так, чтобы вам было 17 лет | Отказ: приложение не пускает дальше и объясняет, что сервис только для 18+ |

| 12 | **Profile → Sign out**, затем снова войдите через Google | Выход работает. При повторном входе данные профиля на месте |

### 3.5. Taker: правила и выход в эфир (устройство A)

| 26 | **Free passes:** 2 | Сохраняется. В эфире виден счётчик пропусков |
| 27 | Посмотрите **Courage score** | Видно стартовое значение и пояснение, от чего оно растёт и падает |
| 28 | Нажмите **Go live**, введите название эфира и подтвердите правила безопасности | iPhone спрашивает доступ к **камере**, затем к **микрофону** |
| 29 | Нажмите **Allow** оба раза | Видно себя на весь экран. Переключение фронтальной и тыльной камеры работает. Есть индикатор LIVE и счётчик зрителей 0 |
| 30 | (Проверка отказа) Завершите эфир, снова **Go live**, но нажмите **Don't Allow** | Приложение не зависает: показывает заставку и объясняет, как включить доступ |

В установленном приложении эти же общие настройки Safari; если доступ так и не появляется, удалите иконку Kurazh с экрана «Домой» и добавьте заново | После этого **Go live** снова показывает камеру |
| 32 | В эфире нажмите **Share**. Покажите QR-код или отправьте ссылку на устройство B (AirDrop, мессенджер) | Ссылка вида `https://b1ueray.github.io/B1ueRay/?watch=<код-комнаты>`. QR читается камерой второго телефона |

### 3.6. Caller на втором устройстве (устройство B)

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| 33 | На B откройте ссылку или наведите камеру на QR. Войдите как **Caller** с возрастом 19 лет | Открывается эфир Taker. Предложить задание нельзя: показано «This Taker accepts dares from 21+ Callers». Смените возраст на 21+ (или используйте другой аккаунт) |

## 4. Ограничения тестовой сборки

- **Данные хранятся на каждом устройстве отдельно** (`localStorage`). Профиль, кошелёк, правила Taker и история не переносятся между телефонами, между Safari и приложением на экране «Домой», и пропадают при очистке данных сайта. Общие для двух устройств только события эфира, которые идут напрямую между ними.
- **Платежи и KYC смоделированы.** Карта тестовая, деньги учебные, заморозки и выплаты — записи на устройстве. Документы и селфи никуда не отправляются, «проверка» всегда успешна. SMS- и email-коды показываются на экране.
- **Эфир идёт через публичный сервер PeerJS** без собственного TURN-сервера. На мобильном интернете (особенно у операторов с общим IP) и в корпоративном Wi-Fi устройства могут не соединиться: зритель видит вечную загрузку. Сначала проверьте, что оба устройства в одном домашнем Wi-Fi. Публичный сервер может быть перегружен или недоступен, это не баг Kurazh. Эфир рассчитан на несколько зрителей, не на сотни.
- **Google ID-токен не проверяется на сервере.** Приложение верит тому, что пришло в браузер. Для теста этого хватает, для настоящих денег — нет.
- **Голосование и Courage score считаются на устройствах.** Их можно подделать, если очень захотеть. В рабочей версии это делает сервер.
- **Фильтр безопасности работает по ключевым словам** на английском, украинском и русском. Его можно обойти опечатками и подменой букв. Видео не модерируется.
- **iOS-особенности:** у приложения на экране «Домой» отдельное хранилище и иногда капризный вход через Google; видео зрителя стартует без звука; при блокировке экрана iPhone эфир Taker останавливается.

## 5. Что нужно для рабочей версии

### 5.1. Архитектура

| Слой | Рекомендация | Зачем |
| --- | --- | --- |
| Бэкенд и аккаунты | В репозитории уже есть приложение на **Next.js + PostgreSQL (Prisma) + Better Auth**. В Better Auth вход через Google включается настройкой `socialProviders.google` (Client ID и Client secret хранятся на сервере в переменных окружения) | Проверка токенов Google на сервере, сессии, роли, правила Taker, общий кошелёк на всех устройствах |
| Real-time | WebSocket-канал (или сервис вроде Ably/Pusher) | Чат, банки заданий, голосование и Courage score считаются на сервере, защита от накруток |
| Живое видео | Управляемый сервис с TURN: **LiveKit Cloud** (WebRTC, задержка < 1 с, свой TURN), **Cloudflare Stream / Realtime** или **Mux Live** (дешевле на большую аудиторию, задержка выше) | Соединение работает на любой сети, масштаб на тысячи зрителей, запись эфиров для разбора жалоб |
| Платежи | PSP с авторизацией и отложенным списанием (**Stripe** с `capture_method=manual` + **Stripe Connect** для выплат Taker'ам; для 18+ нужен high-risk провайдер, например CCBill или Segpay) | Настоящие заморозки и списания, выплаты, налоги. Учтите: авторизация карты держится ограниченное время (у Stripe обычно до 7 дней) |
| KYC и возраст | **Veriff**, **Sumsub**, **Persona** или **Onfido** | Проверка документа и «живого» селфи, возраст 18+/21+ |
| Модерация | Текст: ML-классификатор (например, OpenAI Moderation, Hive). Видео: покадровая проверка (**Hive**, **AWS Rekognition**, Sightengine). Плюс живые модераторы на очередь жалоб | Фильтр по ключевым словам легко обойти |
| Мониторинг | **Sentry** (ошибки фронта и бэка), uptime-мониторинг (Better Stack, UptimeRobot), логи и алерты на платежи | Узнать о проблеме раньше пользователей |
| CI/CD | GitHub Actions: линтер, unit-тесты (Vitest), e2e на **Playwright** с проектами WebKit/iPhone и Chromium/Android; реальные iPhone через BrowserStack или Sauce Labs перед релизом | Ловить регрессии до выкладки |
| Окружения | **staging** и **prod**: отдельные базы, отдельные Google OAuth-клиенты, тестовый режим PSP и KYC на staging | Тесты не трогают настоящие деньги и данные |
| Домен | Свой домен (например, `kurazh.app`), DNS в Cloudflare, HTTPS. Google OAuth переводится в **In production** с проверкой домена и политикой конфиденциальности | Доверие пользователей, проверка приложения Google, ссылки и QR не зависят от github.io |
