# Security review and launch boundaries

Implemented: mature Better Auth password hashing/session handling; server-side role/status/age checks; same-origin mutation validation; Zod input validation; ORM parameterization; atomic PostgreSQL action limits; opaque IDs; private current-entitlement media access; no-store private responses; provider webhook HMAC/constant-time comparison; duplicate event/ledger constraints; transaction/advisory locks; balanced integer accounting; audited administrative decisions; safe mock media; generation review before publication; age state distinct from declaration; current legal acceptances; strict storage path validation; MIME/size validation contract; React escaping; X-Frame-Options, nosniff, referrer/permissions policies and CSP.

Important verified protections include no subscription-based PPV bypass, no cross-account chat read/unlock, no signup role injection, rejected CSRF origins, rejected webhook signatures, no locked-body export bypass and access revocation on refunds. Database constraints prohibit creators below age 21, non-fictional creators and invalid money/tip bounds.

The current CSP permits inline Next.js bootstrap scripts/styles. Adopt per-request nonces and stricter production CSP after compatibility testing. The auth limiter is per process; add a shared limiter or edge anti-abuse service before horizontal scaling. Current keyword moderation does not provide multilingual semantic or adversarial safety guarantees. Manual review is required for all generated assets. Never interpret the mock moderation result as production approval.

Real-person/celebrity generation is not supported. Consent records are schema groundwork and do not unlock a real-person generation path. No governmental identity verification is simulated. Trusted geographic headers require an edge that strips client-supplied values. Verified age callbacks need provider authentication, replay defense and audit.

Demo email delivery stores reset links in a private development-only inbox record; there is no public inbox endpoint. Do not enable that adapter in production. Require a real transactional email provider, verified signup, secure HTTPS cookies and independent random secrets. Disable demo accounts and mock charges before deployment. Consider staff MFA and privileged session policies.

Dependency audit: patched Prisma transitive deepmerge-ts/mysql2 and upgraded Vitest. Production dependencies report zero known advisories in the final audit. The full development tree has an upstream `braces` stack-exhaustion advisory (GHSA-vfj7-8cjw-p6xm) through the official Next.js ESLint plugin/fast-glob; npm currently reports no patched braces version. It is confined to lint tooling, not the production standalone server. Do not pass untrusted glob configuration to lint tasks; update the official tooling when an upstream fix becomes available. See validation evidence for final audit status.

Before launch: independent security/legal review, real age assurance, approved adult-compatible payments, strong moderation, staff training, backups, tamper-resistant external audit retention, data-retention/deletion workflows, queue recovery, provider retry/cost controls, least-privilege database/storage roles, secret management and operational monitoring. These are concrete unfinished integrations, not claims that this demo is already approved for production.
