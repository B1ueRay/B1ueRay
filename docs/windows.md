# Запуск VELORA на Windows

Нужны Windows 10/11 с поддержкой WSL 2 и виртуализации, интернет, Docker Desktop и Git. Node.js, npm и PostgreSQL отдельно устанавливать не нужно: они работают внутри Docker. Запускается та же версия приложения, что в облачной среде, с демонстрационными провайдерами и новой локальной базой данных.

## 1. Установите Docker Desktop

1. Откройте https://www.docker.com/products/docker-desktop/ и скачайте установщик для Windows и архитектуры вашего компьютера.
2. Запустите установщик. Выберите **Use WSL 2 instead of Hyper-V**, если появится этот вариант.
3. Если потребуется WSL, откройте **Пуск**, найдите **PowerShell**, нажмите **Запуск от имени администратора** и выполните `wsl --install`. Перезагрузите компьютер, если система попросит.
4. Откройте Docker Desktop и дождитесь сообщения **Engine running**. Используйте Linux containers. Если Docker сообщает об отключённой виртуализации, включите её в BIOS/UEFI по инструкции производителя компьютера.

## 2. Установите Git

1. Откройте https://git-scm.com/downloads/win и скачайте установщик.
2. Установите Git с настройками по умолчанию.
3. После установки откройте новое окно PowerShell через меню **Пуск**.

## 3. Скачайте и запустите проект

В обычном PowerShell последовательно выполните:

```powershell
cd $HOME
git clone https://github.com/B1ueRay/B1ueRay.git
cd B1ueRay
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-windows.ps1
```

Если папка `B1ueRay` уже существует, сохраните свои локальные изменения, откройте её и выполните `git pull --ff-only` вместо повторного клонирования. Если GitHub попросит авторизацию, войдите в аккаунт с доступом к репозиторию.

Скрипт создаст `.env` с тремя независимыми случайными секретами, установит зависимости внутри образа, соберёт приложение, запустит PostgreSQL и Redis, выполнит миграции и заполнит демоданные. Существующий `.env` сохраняется. Первый запуск может занять несколько минут. PowerShell нужно оставить открытым до завершения команды; после запуска Docker продолжает работу независимо от окна терминала. `ExecutionPolicy Bypass` действует только для этого запуска PowerShell и не меняет постоянную системную политику.

## 4. Откройте сайт

Скрипт откроет браузер автоматически. Точный адрес на вашем компьютере:

**http://localhost:3000**

## Повторный запуск и остановка

Перед запуском откройте Docker Desktop. В PowerShell из папки проекта:

```powershell
docker compose up -d --wait
```

Остановка с сохранением базы и медиа:

```powershell
docker compose down
```

Не добавляйте `-v`: это удаляет локальные данные. Docker Desktop должен работать, пока вы используете сайт.

## Если запуск не удался

- **Порт 3000 или 5432 занят:** остановите другое приложение/контейнер, использующее этот порт, и повторите запуск скрипта.
- **Docker не отвечает:** откройте Docker Desktop и дождитесь готовности движка.
- **Не открывается страница:** выполните `docker compose ps` и `docker compose logs --tail 100` из папки проекта. У `web` и `db` должен быть статус `healthy`; успешное завершение `init` нормально.
- **Ошибка загрузки образов или пакетов:** проверьте интернет и настройки прокси Docker Desktop, затем повторите скрипт. Проверки TLS отключать не нужно.

Контейнерный запуск проверен в облачной Linux-среде. Сам PowerShell-скрипт в Windows здесь не исполнялся.
